# 为学日益，为道日损

> 为学日益，为道日损。损之又损，以至于无为。无为而无不为。
>
> —— 《道德经》第四十八章

这是 q-body 的项目宪法。它不是装饰，是每一次 commit、每一个 PR、每一次学习之后必须回头看的判据。

---

## 三层结构

```
soul/TAO.md   道 — 不变的心法（本文件，损的纪律）
soul/SOUL.md  神 — 生长的人格（益的沉淀，public）
soul/SELF.md  私 — 亲密的自我（private，不公开）
src/          形 — 极简的身体（趋于无为）
```

**道不变，神生长，形趋简。**

---

## 为学日益 —— LEARNINGS.md 的职责

学习不设上限。

- 学 yoyo-evolve、AgentScope、LangGraph、MCP——**见闻要广，输入要多**
- LEARNINGS.md 只增不删。即使某个模式被否决，也要留下"为什么否决"的判例
- 每次阅读大项目后，回答三个问题：
  1. 它解决了什么我没有的问题？
  2. 它的方案里，哪一层抽象是"非它不可"的？
  3. 如果我只抄一件事，抄什么？

**益的戒律**：见识无禁，但**抄模式不抄架构**。大框架的抽象层是为多租户/多团队设计的，q-body 只有一个用户。

---

## 为道日损 —— 代码库的职责

代码设上限。

### 硬上限

| 维度 | 上限 | 现状 | 说明 |
|---|---|---|---|
| Rust 代码总行数 | **≤ 3000 行** | 1157 | `find src -name '*.rs' \| xargs wc -l` |
| 直接依赖数 | **≤ 15 个** | 14 | `Cargo.toml [dependencies]` |
| src/ 文件数 | **≤ 12 个** | 7 | 文件即模块边界，不随意拆分 |
| 单文件行数 | **≤ 500 行** | handler.rs ~260 | 超过即拆，但拆前先问能否删 |

### 每个 PR 必须回答

在 PR body 里必填一句：

> **这次损掉了什么？**

允许的答案：
- 删掉了 X 行冗余代码
- 删掉了 Y 个依赖
- 删掉了 Z 个抽象层（合并了 A 和 B）
- **"没有损，只有增"——需要额外 justification 说明为什么这个功能不能放进 SOUL.md**

### 损的判据

一个功能该写进 Rust 还是放进 SOUL.md？

| 情况 | 放在哪里 |
|---|---|
| 提示词、人格、语气、价值观 | SOUL.md |
| 记忆、经验、学习笔记 | journal/ 或 LEARNINGS.md |
| 协议解析、加密、异步运行时 | Rust |
| 简单 if-else 决策 | SOUL.md（提示词即可） |
| 复杂状态机、性能敏感路径 | Rust |
| 一次性脚本逻辑 | 不进代码库，走 cron 或手动 |

> **判据：如果 LLM 能直接做对，就不写代码。代码是 LLM 做不到的事。**

## 损之又损，以至于无为 —— 终极形态

q-body 的目标形态：

- **身体（Rust）**：只是协议转换（A2A JSON-RPC ↔ LLM API）+ 记忆读写（SOUL.md/journal），几乎"无为"
- **灵魂（SOUL.md）**：承载一切个性、经验、偏好、成长——**代码越无为，灵魂越自由**
- **LLM 可换、框架可弃、语言可重写**，因为道不在身体里

### 无为的检验

想象五年后：
- axum 过时了 → 换成下一个框架，只动 `main.rs` 的 bind 和 router
- Rust 不再是最佳选择 → 用 Go/Zig/whatever 重写 3000 行，一周完成
- LLM API 形态彻底改变 → 只动 `a2a/llm.rs` 的 endpoint 调用

**如果换个 LLM provider 需要动超过 3 个文件，说明身体还不够无为。**

## 对抗"变重"的工程纪律

### 1. 拒绝框架化，坚持协议化

- A2A 协议 → 自实现 JSON-RPC 解析（已有，300 行）
- MCP 协议 → 同样是 JSON-RPC，复用现有模式，不引入 SDK
- Tool calling → `trait Tool + Vec<Box<dyn Tool>>`，不需要三层 Toolkit registry

### 2. 依赖纪律

每加一个 crate，在 LEARNINGS.md 里记录：

```markdown
## YYYY-MM-DD: 新增依赖 `xxx`
- **为什么非加不可**：手写的成本 / 安全隐患 / 协议复杂度
- **替代方案为什么不行**：
- **损掉了什么**：（比如删掉了自己手写的 200 行 JSON 解析）
```

### 3. 学习大项目后的"抄什么"清单

| 项目 | 抄模式 | 不抄架构 |
|---|---|---|
| yoyo-evolve | 自我修复回路（health check → diagnose → fix） | 不抄它的多 agent 编排 |
| AgentScope | RUBRIC 评估模式（未来 memory 质量评估可参考） | 不抄 Middleware Onion、Toolkit 三层抽象 |
| LangGraph | 状态机可视化思路（未来 journal 分析可参考） | 不抄 Graph 编排 |

### 4. 记忆的优先级 > 能力的优先级

| 优先级 | 功能 | 理由 |
|---|---|---|
| P0 | journal/ JSONL 追加 | 每次对话后追加结构化日志 |
| P0 | SOUL.md 注入 system prompt | 灵魂接回身体 |
| P1 | 睡眠压缩（journal → SOUL 经验章节） | 自进化的最小闭环 |
| P1 | soul/EVOLUTION.md | 人格修订的 diff 记录 |
| P2 | /growth 端点 | 成长可视化 |
| P3 | 新工具、新协议、新 provider | 永远不紧急 |

**task 历史可以丢，人格积累不能丢。**

## 它自己参与进化

q-body 的自进化不是"自己改代码"，而是：

```
收到反馈 → 写入 journal → 定期生成"我想怎么改自己"的提案（markdown）
  → 老板审核 → 变成 commit
```

**人做守门员，agent 做提案者。** 这是个人规模下最安全也最有趣的自进化形态。

>
> **轻，不是妥协，是定位。**
>
> **为学日益，为道日损——大多数 agent 死于前者而不肯后者，q-body 要守住这八个字。**
