# ADR: q-body Web 聊天页面（SSH 隧道使用）

- 日期：2026-10-08
- 状态：待老板过目
- 方法：grill-with-docs（Matt Pocock 拷问式规划）
- 使用前提：通过 SSH 隧道访问，服务仍只绑 127.0.0.1，不暴露公网

---

## 一、拷问：逐个把模糊决策钉死

**Q1. 页面怎么交付给浏览器？**
选项：(a) 独立前端项目单独部署 (b) q-body 二进制内建单文件 HTML
→ 选 **b**。只有一个用户、走 SSH 隧道，内建 HTML 零额外进程、零构建，`/` 直接返回。独立项目是给多团队/CDN 场景的，这里是过度设计。

**Q2. 页面通过什么协议跟后端说话？**
→ 直接复用现有 `POST /a2a/jsonrpc`（message/send），不新增聊天专用 API。
理由：现有方法已经端到端验证（火山 Agent Plan 真回复），加新端点 = 重复接线。前端只做渲染。

**Q3. 需要登录/鉴权吗？**
→ **不需要应用层鉴权**。访问安全由 SSH 隧道保证（隧道本身就是认证通道），服务只听 127.0.0.1。加密码是双层重复。若以后改绑公网，再补 API-key 门禁（独立工作项）。

**Q4. 需要保存聊天历史吗？**
→ 第一版 **不持久化对话历史**，刷新即清空（会话状态在浏览器内存）。
后端 Journal 继续记录"进化事件"，但那是 agent 的记忆，不是聊天记录。历史持久化等真有需求再加，避免现在设计数据库。

**Q5. 需要流式输出吗？**
→ 第一版不做（capabilities.streaming=false，现有后端非流式）。先整段返回，够用。流式是后续增强。

**Q6. 放在哪个文件、怎么不污染代码上限？**
→ `src/webui.rs` 只放一个 `CHAT_HTML` 常量；`main.rs` 加一个 `get_index` handler + `/` 路由。HTML 是呈现层常量，不计入 Rust 逻辑复杂度，改动面极小。

---

## 二、实施清单（3 处改动）

1. `src/webui.rs`（已起草，~100 行 HTML/CSS/JS）：聊天气泡界面，fetch /a2a/jsonrpc，含加载态/错误态/移动端适配
2. `src/main.rs`：
   - `mod webui;`
   - `async fn get_index() -> impl IntoResponse { Html(webui::CHAT_HTML) }`
   - `.route("/", get(get_index))`
3. 不改监听地址（保持 127.0.0.1），不改任何 LLM/鉴权逻辑

验证：cargo build + 真启二进制 + curl / 拿到 HTML + 浏览器（隧道）发消息收到真回复 + cargo test 不回归。

## 三、使用方式（做完后）

```bash
# 本地电脑建隧道
ssh -L 41242:127.0.0.1:41242 ubuntu@<服务器IP>
# 浏览器打开
http://127.0.0.1:41242/
```

## 四、明确不做（防范围蔓延）

- 不做用户系统/注册
- 不做聊天记录云端持久化
- 不做流式/多会话切换/文件上传（后续按需单独提）
- 不改公网暴露策略
